> [!操作系统涉及的基本概念，可以归纳为**六个核心支柱**。你提到的“并发”正是其中之一。下面我用最简方式解释每个概念，并说明它们如何回答“OS要完成的那三件事”（抽象、虚拟化、保护）。

---

### 1. 并发（Concurrency）
- **是什么**：多个任务**看起来同时**在往前推进（即使单核CPU也只是高速切换）。
- **关键问题**：任务之间会互相干扰（比如两个程序同时修改同一个变量），需要**同步**机制（锁、信号量）。
- **OS做的事**：进程/线程调度、提供同步原语。

### 2. 虚拟内存（Virtual Memory）
- **是什么**：让每个程序以为自己拥有完整、连续的内存空间（从0到很大），而实际物理内存可能很小且碎片化。
- **关键机制**：地址转换（MMU + 页表）、按需分页、交换空间。
- **OS做的事**：管理页表、处理缺页异常、决定哪些页面留在内存。

### 3. 文件系统（File System）
- **是什么**：把磁盘的原始块包装成**目录、文件名、文件数据流**。
- **关键机制**：inode、目录项、数据块分配、缓存。
- **OS做的事**：创建/删除/读写文件、管理磁盘空间、保证持久性。

### 4. 进程与线程（Process & Thread）
- **进程**：一个正在运行的程序实例，拥有独立的地址空间、文件句柄等资源。
- **线程**：进程内的一个执行流，共享进程的资源（内存、文件），但有自己的栈和寄存器。
- **OS做的事**：创建/销毁进程/线程、上下文切换、进程间通信（IPC）。

### 5. 系统调用（System Call）
- **是什么**：用户程序请求OS服务的唯一入口（如读文件、创建进程、分配内存）。
- **关键机制**：陷入内核（软中断或`syscall`指令）、特权级切换。
- **OS做的事**：验证参数、执行特权操作、返回结果。

### 6. 中断与异常（Interrupt & Exception）
- **中断**：来自硬件（时钟、键盘、磁盘）的异步信号，强制CPU跳转到OS的中断处理程序。
- **异常**：来自CPU内部（除零、缺页、非法指令）的同步事件。
- **OS做的事**：保存当前状态，根据中断/异常类型调用相应处理函数（如缺页异常→调入内存，时钟中断→调度）。

---

### 辅助概念（常与上面混用，但更具体）
- **死锁**：两个或多个进程互相等待对方释放资源，导致永远阻塞。OS需要提供死锁避免/检测/恢复机制。
- **缓存**：OS大量使用缓存（页缓存、dentry缓存、缓冲区缓存）来提升性能，但必须解决一致性问题。
- **原子操作**：不可分割的操作，用于实现锁和同步。
- **调度算法**：决定下一个运行哪个进程/线程（如轮转、优先级、多级队列）。

---

### 一张图记住它们的关系
```
用户程序
   │
   └── 系统调用 ──┐
                  ↓
              内核
   ┌─────────────┴─────────────┐
   │ 进程管理    内存管理    文件系统 │
   │ (并发/调度) (虚拟内存)   (inode) │
   └─────────────┬─────────────┘
                 │
          中断/异常/时钟
                 │
              硬件
```

**总结**：操作系统课程就是围绕这六根支柱展开的。建议你先完全理解**进程与并发**（因为其他概念依赖它），然后再看**虚拟内存**，最后是**文件系统**。中断和系统调用是贯穿始终的“管道”。

这段代码演示了 Linux 中 `fork()` 系统调用的基本行为。下面逐步解释其原理和输出结果。

## 1. 程序流程分析

```c
printf("fork test...\n");   // ① fork 之前
pid = fork();               // ② 创建子进程
if (pid < 0) { ... }        // ③ 错误处理
printf("======%d=======\n", getpid()); // ④ 父子进程都会执行
```

- **步骤①**：父进程执行，输出 `fork test...`（此时只有一个进程）。
- **步骤②**：`fork()` 被调用。系统创建一个**几乎完全相同的子进程**：
  - 子进程复制父进程的代码段、数据段、堆、栈、文件描述符等。
  - 父子进程从此**独立运行**，各自拥有独立的内存空间（写时复制技术优化性能）。
- **步骤③**：`fork()` 在父进程中返回子进程的 PID（正整数），在子进程中返回 0。若失败返回 -1。
- **步骤④**：无论父子，都会执行这条 `printf`。由于两个进程的 `getpid()` 不同，打印的 PID 自然不同。

==————==
## 2. 为什么 `fork test...` 只打印一次？
==————==

因为 `printf` 在 `fork()` **之前**执行，此时只有一个进程。`fork` 复制了整个进程，包括已经输出到终端的内容（但终端输出是已完成的 I/O，不会重复）。所以父进程打印一次，子进程不会重新打印该行。

## 3. 输出顺序为何不确定？

```
fork test...
======36695=======
======36696=======
```

输出中两个 `======` 行的先后顺序**取决于操作系统调度器**。`fork` 之后，父子进程成为两个独立的可执行实体，谁先获得 CPU 谁就先执行 `printf`。在你的运行结果中，父进程（36695）先输出，子进程（36696）后输出；但下一次运行完全可能反过来。

> 事实上，`fork` 之后通常立即有两个进程并行/并发执行，输出的交错现象在多行打印时更明显。

## 4. 关键点总结

| 概念 | 说明 |
|------|------|
| `fork()` 返回值 | 父进程得到子进程 PID；子进程得到 0。 |
| 代码执行点 | 子进程从 `fork()` 返回处开始执行（不是从头）。 |
| 共享与独立 | 父子进程内存独立，但文件描述符等共享（指向同一内核对象）。 |
| 缓冲区影响 | 如果 `printf` 不带 `\n`，可能因缓冲区在 `fork` 时被复制导致重复打印。本例带有 `\n`，行缓冲立即刷新，无副作用。 |

## 5. 延伸思考

如果希望父子进程执行不同的逻辑，可以这样区分：

```c
if (pid == 0) {
    // 子进程代码
    printf("I am child, PID=%d\n", getpid());
} else {
    // 父进程代码
    printf("I am parent, child PID=%d\n", pid);
}
```

你的代码没有做区分，所以两个进程都执行了相同的 `printf`。
